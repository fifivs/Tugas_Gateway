Alur Kerja Sistem

Bagaimana setiap request diproses di dalam API Gateway

Step-by-Step Proses
1
Validasi Request (JWT)

Token JWT diperiksa keasliannya menggunakan algoritma HS256. Jika kadaluarsa atau palsu, request langsung ditolak.

2
Rate Limiting

Sistem membatasi maksimal 30 request per 60 detik per user untuk mencegah penyalahgunaan dan serangan DDoS.

3
Logging ke Database

Setiap request yang masuk dicatat di database MySQL untuk keperluan audit, monitoring, dan analitik real-time.

4
Hitung Biaya Layanan (Fee 0.5%)

Gateway menghitung fee 0.5% dari jumlah transaksi secara otomatis sebagai biaya layanan integrasi.

5
Routing ke SmartBank (Backtracking)

Data transaksi diteruskan ke SmartBank menggunakan algoritma backtracking failover — jika primary route gagal, otomatis backtrack ke alternatif.

6
Respons ke Konsumen

Hasil dari SmartBank dikembalikan ke konsumen beserta info fee, trace backtracking, dan catatan integrator.

POST /integrator/routing_api

Kirim transaksi melalui gateway ke SmartBank. Request divalidasi, di-log, dihitung fee-nya, lalu diteruskan.

FieldTipeKeterangan
user_idstringID pengguna
parameter.tokenstringToken JWT untuk autentikasi
parameter.amountnumberJumlah transaksi
Response Sukses
{ "status": "sukses", "data": { "integrator_note": "...", "fee_diambil": 500.0, "respons_dari_smartbank": { ... } } }
POST /integrator/routing_universal

Forward request ke app UMKM manapun. Wajib isi target_app. Sudah include rate limiting, validasi JWT, dan logging otomatis.

FieldTipeKeterangan
user_idstringID pengguna
parameter.tokenstringToken JWT
parameter.target_appstringID app tujuan (smartbank/marketplace/pos/supplierhub/logistikita/umkminsight)
parameter.amountnumberJumlah transaksi (opsional)
parameter.target_endpointstringOverride endpoint tujuan (opsional)
Response Sukses
{ "status": "sukses", "data": { "target_app": "marketplace", "fee_gateway": 250, "fee_persen": "0.5%", "response_time_ms": 42 } }
